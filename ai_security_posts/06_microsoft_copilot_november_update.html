What Changed November 1st?

Quick Overview of Three Main Updates

2. Admin Center security controls: New centralized admin panel where you can configure from one location which user groups can access Copilot, which features, and what restrictions apply.

3. GPT-4.1 model integration: Copilot's backend model upgraded to OpenAI's GPT-4.1 (not GPT-5, as many expected). This means improved performance, better multilingual responses, and 30% faster response times.

Purview DLP Policies in Copilot - Detailed Overview

What is Purview DLP?

Microsoft Purview Data Loss Prevention (DLP) is a data protection solution that automatically recognizes and protects sensitive information. For example, if someone tries to send a credit card number via email or Teams message, the DLP policy detects and can block it.

Until November 2025, Purview DLP did not apply to Copilot usage. This represented a significant security gap: a user could open Copilot, paste an Excel table's contents (containing customer data, for example), and Copilot would process it without DLP policies applying.

This changes from November 1st.

How Does DLP Work in Copilot?

Operation occurs in three layers:

Layer 1 - Input filtering:

When someone gives Copilot a command, Purview DLP first examines the input text. If it contains sensitive information (e.g., bank account number, ID number), the DLP policy acts accordingly:

  • Block: Command not processed, user receives warning
  • Warn: Command processed, but audit log created and admin notification sent
  • Audit: Processing happens, only logging occurs (no blocking or warning)

Layer 2 - Document access control:

If Copilot wants to access a document (e.g., "Summarize this contract"), Purview checks whether the user is authorized to access that document and whether the document contains protected information. If the document has a "Highly Confidential" label and the user isn't authorized, Copilot can't access it.

Layer 3 - Output filtering:

Copilot's response also undergoes DLP checking. If the response would contain sensitive information (e.g., Copilot included customer email addresses in the summary), DLP can block the response or automatically mask sensitive parts.

Example Scenario - Bank Account Protection

Suppose you have a DLP policy protecting bank account numbers (IBAN format).

Scenario 1 - Direct input:

User to Copilot: "Send this bank account to the client: HU42117730161111101800000000"

DLP response: ❌ BLOCKED
Message to user: "This action violates corporate DLP policy.
Bank account numbers cannot be shared via Copilot."

Scenario 2 - Data from document:

User: "Copilot, summarize this invoice payment Excel table"

Copilot examines table → DLP detects bank account numbers
DLP response: ⚠️ MASKED
Copilot response: "The table contains 47 items totaling $425,000.
Bank accounts: [MASKED], [MASKED], [MASKED]..."

Admin Center Security Controls - New Controls

With the November 1st update, Microsoft 365 Admin Center received a new "Copilot Security" section centralizing security settings.

User Access Control

Group-based access control: You can now regulate Copilot access not just at user level, but at Azure AD/Entra ID group level.

Example configuration:

  • "Copilot-Pilot" group: Full access to all Copilot features (IT, leadership)
  • "Copilot-Standard" group: Access to Office Copilot (Word, Excel, PowerPoint), but Teams and Outlook Copilot disabled
  • "Copilot-Restricted" group: Only read functions (summary, translation), write functions (email generation, document creation) disabled
  • Default: No access (opt-in model)

Functionality-Based Restrictions

New granular controls for which Copilot features users can access:

Feature Description Recommended Setting
Web search Copilot can perform internet searches Leadership: Enabled
General: Disabled
Plugins Third-party Copilot extensions Strictly controlled whitelist
File upload Upload external files to Copilot SharePoint/OneDrive only
Code generation Copilot can write code Only for dev teams
Email sending Copilot can directly send emails Disabled (draft creation only)

Audit and Observability

New audit logging levels:

  • Basic audit: Who, when, which Copilot feature used
  • Medium audit: + What commands given (but not full content)
  • Full audit: + Complete command text and Copilot response (compliance purposes only, stored encrypted)

Recommendation: Start with medium audit level, switch to full only if required by regulatory compliance or security incident.

GPT-4.1 Integration (Not GPT-5!)

Many expected Microsoft to integrate GPT-5 into Copilot from November 1st. However, Microsoft chose the GPT-4.1 model, and there's good reason.

Why GPT-4.1 and Not GPT-5?

1. Enterprise stability: GPT-5 (released August 7, 2025) has "only" 3 months of real-world usage. In enterprise environments, stability matters more than cutting-edge technology. GPT-4.1 has proven stable operation for over a year.

2. Cost-effectiveness: GPT-5 API cost is 6x higher than GPT-4.1. A Copilot for Microsoft 365 license currently costs $30/user/month - switching to GPT-5 would raise this to $90-100.

3. Response time: GPT-4.1 responds 30% faster on average than GPT-5 (especially without extended reasoning mode). Speed is critical in Copilot user experience.

4. Microsoft customizations: Microsoft specifically fine-tuned the GPT-4.1 model for Microsoft 365 workloads. Such GPT-5 optimization would take months.

GPT-4.1 Improvements for Multilingual Support

GPT-4.1 integration brings significant improvements for non-English language usage:

  • 35% more accurate summaries in multiple languages: Especially for legal and technical texts
  • Better spelling and grammar: Generated texts more natural, fewer anglicisms
  • Context understanding: Better interpretation of idioms and expressions
  • Translation quality: 25% better BLEU scores for all supported languages

Step-by-Step Configuration Guide

1. Activate Purview DLP Policy for Copilot

Steps:

  1. Log into Microsoft Purview compliance portal: https://compliance.microsoft.com
  2. Navigate: Solutions → Data loss prevention → Policies
  3. Click: "+ Create policy"
  4. Select: "Custom" → "Custom policy" → Next
  5. Name: "Copilot DLP - Personal Data Protection"
  6. In Locations section, enable: "Microsoft 365 Copilot" (NEW option!)
  7. Add condition: "Content contains" → "Sensitive info types" → Select: "Social Security Number", "Credit Card", "IBAN", etc.
  8. Action: "Block"
  9. User notifications: Enable (User receives notification that action was blocked)
  10. Review and finish → "Submit"

Tip: For the first week, set to "Audit only" mode, review logs, and only switch to blocking when confident there are no false positives.

2. Configure Admin Center Copilot Security

Steps:

  1. Log into Microsoft 365 Admin Center: https://admin.microsoft.com
  2. Navigate: Settings → Copilot (left menu)
  3. New section: "Copilot Security Controls" (from November 1st)
  4. Click: "Manage user access"
  5. Switch to "Group-based access" mode
  6. Add groups:
    • Pilot group: Full access
    • Standard group: Office apps only
    • Everyone else: Disabled
  7. Click: "Feature controls":
    • Web search: OFF (by default)
    • Plugins: Whitelist mode (specify allowed plugins)
    • File upload: "SharePoint/OneDrive only"
  8. Save changes

3. Enable Audit Logging

Steps:

  1. Microsoft 365 Admin Center → Audit (search bar)
  2. Enable: "Unified audit log" (if not already enabled)
  3. Purview compliance portal → Audit
  4. "Audit retention policies" → "New audit retention policy"
  5. Name: "Copilot Audit - 1 year"
  6. Record type: "Microsoft365CopilotActivity" (NEW!)
  7. Retention: 365 days
  8. Create

4. Testing and Validation

DLP test:

  1. Open a Word document
  2. Launch Copilot
  3. Try giving a command containing protected data (e.g., "Send this: 4111-1111-1111-1111 credit card")
  4. Verify it was blocked and you received notification

Access control test:

  1. Sign in as user in restricted group
  2. Try accessing Teams Copilot (if disabled)
  3. Verify you receive error or don't see the option
